| 层 | 职责 | 技术 |

| 客户端层 | 用户交互界面 | 微信原生 + Vue3 CDN |

### 2.2 表结构详细设计

#### 2.2.1 用户表 (user)

```sql
CREATE TABLE `user` (
    `id`            BIGINT       NOT NULL AUTO_INCREMENT COMMENT '用户ID',
    `openid`        VARCHAR(64)  NOT NULL COMMENT '微信OpenID',
    `nickname`      VARCHAR(64)  DEFAULT '' COMMENT '用户昵称',
    `avatar_url`    VARCHAR(512) DEFAULT '' COMMENT '头像URL',
    `phone`         VARCHAR(20)  DEFAULT '' COMMENT '手机号',
    `role`          TINYINT      NOT NULL DEFAULT 0 COMMENT '角色: 0-普通用户, 1-管理员',
    `status`        TINYINT      NOT NULL DEFAULT 1 COMMENT '状态: 0-禁用, 1-正常',
    `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
    `updated_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_openid` (`openid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 2.2.2 物品信息表 (item)

**设计决策**：失物和招领合并为一张表，通过 `type` 字段区分。理由：
- 字段结构一致，减少表数量
- 智能匹配时查询更简单（同一张表JOIN）
- 维护成本低

```sql
CREATE TABLE `item` (
    `id`              BIGINT       NOT NULL AUTO_INCREMENT COMMENT '物品ID',
    `user_id`         BIGINT       NOT NULL COMMENT '发布者ID',
    `type`            TINYINT      NOT NULL COMMENT '类型: 0-失物, 1-招领',
    `title`           VARCHAR(100) NOT NULL COMMENT '标题',
    `description`     TEXT         NOT NULL COMMENT '物品描述',
    `category_id`     INT          NOT NULL COMMENT '分类ID',
    `location`        VARCHAR(200) NOT NULL COMMENT '丢失/拾取地点',
    `item_date`       DATE         NOT NULL COMMENT '丢失/拾取日期',
    `contact`         VARCHAR(100) DEFAULT '' COMMENT '联系方式',
    `status`          TINYINT      NOT NULL DEFAULT 0 COMMENT '状态: 0-待审核, 1-已发布, 2-审核不通过, 3-已解决',
    `ai_category`     VARCHAR(50)  DEFAULT '' COMMENT 'AI识别的分类',
    `ai_description`  TEXT         DEFAULT NULL COMMENT 'AI生成的增强描述',
    `ai_ocr_text`     TEXT         DEFAULT NULL COMMENT 'OCR识别文字',
    `ai_features`     JSON         DEFAULT NULL COMMENT 'AI提取的特征向量/标签(JSON)',
    `view_count`      INT          NOT NULL DEFAULT 0 COMMENT '浏览次数',
    `created_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at`      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_type_status` (`type`, `status`),
    KEY `idx_category_id` (`category_id`),
    KEY `idx_location` (`location`),
    KEY `idx_item_date` (`item_date`),
    KEY `idx_created_at` (`created_at`),
    FULLTEXT KEY `ft_title_desc` (`title`, `description`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='物品信息表';
```

## 四、AI服务设计（重点）

### 4.1 统一AI服务接口

采用**策略模式 + 工厂模式**，支持多AI厂商切换：

```
┌──────────────────────────────────────┐
│           AiService (接口)           │
│  ├─ recognizeImage(MultipartFile)    │
│  ├─ describeImage(MultipartFile)     │
│  ├─ ocr(MultipartFile)              │
│  ├─ chatWithImage(img, text)        │
│  ├─ auditContent(text)              │
│  └─ getTextEmbedding(text)          │
└──────────────┬───────────────────────┘
               │ implements
    ┌──────────┼──────────┬──────────────┐
```

```java
public interface AiService {
```

### 4.3 智能匹配算法设计

```
发布新物品
    │
    ▼
提取多维特征
    │
    ├── 调用AI获取图片描述
    ├── 调用AI获取文本向量
    ├── 已有OCR结果
    ├── 已有分类
    ├── 地点信息
    └── 时间信息
    │
    ▼
遍历对端物品库（失物↔招领）
    │
    ▼
计算6维度匹配度：
┌──────────────┬────────┬──────────────────────────┐
│    维度      │  权重  │      计算方法             │
├──────────────┼────────┼──────────────────────────┤
│ 图片相似度   │  25%   │ AI描述文本 → 向量余弦相似度 │
│ 文本语义     │  25%   │ 标题+描述 → 向量余弦相似度  │
│ OCR匹配      │  15%   │ OCR文本关键词匹配           │
│ 分类匹配     │  15%   │ 同分类=满分，相近分类=半分  │
│ 地点匹配     │  10%   │ 同地点=满分，同区域=半分    │
│ 时间匹配     │  10%   │ 时间差<3天=满分，<7天=半分  │
└──────────────┴────────┴──────────────────────────┘
    │
    ▼
加权求和 → 总分(0-100)
    │
    ▼
总分 ≥ 阈值(60) → 生成MatchRecord → 通知双方
```

### 4.4 AI接口异步处理

考虑到AI调用耗时较长（2-5秒），发布物品时的AI处理流程：

```
用户提交发布
    │
    ▼
保存物品信息到数据库 (status=待审核)
    │
    ▼
立即返回成功 (响应时间 < 300ms)
    │
    ▼
异步执行 (CompletableFuture / @Async):
├── AI图片识别 → 更新ai_category
├── AI图片描述 → 更新ai_description
├── OCR识别    → 更新ai_ocr_text
├── 图文理解   → 更新ai_description(增强版)
└── 智能匹配   → 生成MatchRecord
    │
    ▼
匹配到 → 推送通知
```

## 六、关键设计决策说明

| # | 决策点 | 方案 | 理由 |
|---|--------|------|------|
| 1 | 失物/招领 | 同一张item表，type区分 | 字段一致，匹配查询方便 |
| 2 | 管理后台 | 独立HTML SPA | 开发简单，演示效果好 |
| 3 | AI服务 | 策略模式+工厂模式 | 多厂商灵活切换 |
| 4 | AI处理 | 异步(@Async) | 响应快，用户体验好 |
| 5 | 图片存储 | MinIO | 开源S3兼容，部署简单 |
| 6 | 文本搜索 | MySQL FULLTEXT | 数据量小时够用，避免引入ES |
| 7 | 图片匹配 | AI描述→向量→余弦相似度 | 无需CLIP模型，实现简单 |
| 8 | 分类管理 | 字典表 | 支持后续扩展分类 |
