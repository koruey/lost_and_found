## 四、数据库设计概要（10张表）

| 表名 | 核心字段 | 关键索引 |
|------|----------|----------|
| `user` | id, openid(UK), nickname, avatar_url, phone, role, status | uk_openid |
| `category` | id, name, icon, sort_order | 预置15个分类 |
| `item` | id, user_id, **type**(0失物/1招领), title, description, category_id, location, item_date, contact, **status**(0待审/1发布/2驳回/3解决), ai_category, ai_description, ai_ocr_text, ai_features(JSON), view_count | idx_type_status, idx_category, idx_location, FULLTEXT(title+desc) |
| `item_image` | id, item_id, url, thumbnail_url, sort_order | idx_item_id |
| `favorite` | id, user_id, item_id | uk_user_item(联合唯一) |
| `comment` | id, item_id, user_id, content, status(0正常/1删除) | idx_item_id |
| `notification` | id, user_id, type(0匹配/1评论/2审核/3系统), title, content, related_id, is_read | idx_user_read |
| `announcement` | id, title, content, status(0隐藏/1显示) | - |
| `match_record` | id, lost_item_id, found_item_id, **total_score**, image_score, text_score, ocr_score, category_score, location_score, time_score, reason, status | idx_score DESC |
| `ai_audit_log` | id, target_type(0物品/1评论), target_id, result(0通过/1违规), reason | idx_target |

### 关键设计决策

- **失物/招领合并** → 同一张item表，type字段区分，匹配查询方便
- **AI字段独立** → ai_category/ai_description/ai_ocr_text 不覆盖用户原始输入
- **匹配维度化** → match_record记录6维分项分数，可追溯可解释
- **评论软删除** → status=1标记删除
- **分类字典化** → category表管理，支持扩展

## 九、开发规范速查

### 后端规范
1. **统一返回** → 全部使用 `Result<T>` 包装
2. **异常处理** → `throw new BusinessException(ErrorCode.XXX)`
3. **参数校验** → `@Valid` + Validation注解
4. **认证校验** → Controller内手动 `checkLogin(userId)`
5. **分页** → 使用 `PageResult<T>`，默认 page=1, size=10
6. **常量** → 魔法数字统一使用 `Constant` 类

### 前端对接规范
1. **请求头** → `Authorization: Bearer {token}`
2. **Token管理** → Storage存取，封装在auth.js
3. **图片流程** → 先上传获取URL，再提交物品
4. **AI流程** → 上传→AI识别/描述/OCR(可并行)→增强→用户确认→提交
5. **响应解析** → 统一格式 `{code, message, data, timestamp}`，code=200为成功

### 关键常量速查
| 常量 | 值 | 含义 |
|------|----|------|
| ITEM_TYPE_LOST | 0 | 失物 |
| ITEM_TYPE_FOUND | 1 | 招领 |
| ITEM_STATUS_PUBLISHED | 1 | 已发布 |
| ITEM_STATUS_RESOLVED | 3 | 已解决 |
| ROLE_ADMIN | 1 | 管理员 |
| MATCH_THRESHOLD | 60.0 | 匹配阈值 |
| REDIS_TOKEN_PREFIX | "token:" | Token缓存Key |
