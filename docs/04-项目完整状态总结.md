## 一、项目名称与目标

**项目名称**：基于多模态AI的校园失物招领微信小程序设计与实现

**核心目标**：为大学校园提供一套"发布失物/招领 → AI自动识别分类描述 → 智能匹配 → 通知失主"的全链路解决方案。

**核心创新点 — 多模态AI的7大功能**：

| # | 功能 | 说明 |
|---|------|------|
| 1 | 图片识别分类 | 上传图片 → AI自动判断物品类别（手机/钥匙/校园卡等15类） |
| 2 | 图片描述生成 | AI生成物品外观的文字描述 |
| 3 | OCR文字识别 | 从图片中提取文字（身份证号、学生卡信息等） |
| 4 | 图文联合理解 | 结合用户描述+图片生成增强描述 |
| 5 | 智能匹配推荐 | 失物/招领6维加权匹配(Jaccard 2-gram)，阈值≥60% |
| 6 | AI内容审核 | 自动审核发布内容，过滤违规信息 |
| 7 | AI分类辅助 | AI建议分类 → 用户确认 → 自动填充 |

**技术路线**：微信小程序原生 (WXML+WXSS+JS) + 管理后台 (Vue3 CDN单HTML) + Spring Boot 3.2.7 + MyBatis Plus 3.5.7 + MySQL 8 + Redis + MinIO + JWT，前后端分离架构。

### 关键技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 失物/招领表设计 | **单表** item(type字段区分) | 简化匹配查询，避免JOIN |
| 认证方案 | **JWT可选模式** | 拦截器始终放行，Controller手动checkLogin，公共接口无需登录 |
| AI多厂商 | **策略+工厂模式** | OpenAI兼容API覆盖3厂商，Claude独立实现 |

| 小程序框架 | **微信原生** | 不使用第三方框架，轻量可控 |
| 小程序UI | **WeUI扩展库** | 微信内置，无需npm，useExtendedLib引入 |
| 管理后台 | **Vue3 CDN单HTML** | Element Plus + ECharts CDN，零构建，浏览器直开 |

### 4.4 认证与拦截器核心设计

```
JwtInterceptor (preHandle永远返回true)
  └─ 解析 Authorization: Bearer {token}
     ├─ 有效（JWT签名正确+Redis中存在）→ request.setAttribute("userId", userId)
     └─ 无效/缺失 → 不设置userId (放行)

AdminInterceptor (拦截 /api/admin/**，排除 /api/admin/login)
  └─ 读取 request.getAttribute("userId")
     └─ 查 Redis key: "user:{userId}:role"
        ├─ role==1(管理员) → true
        ├─ userId==null → 401
        └─ 非管理员 → 403

Controller层
  → 公共接口: @RequestAttribute(required=false) + 不检查userId
  → 需认证接口: @RequestAttribute(required=false) + if(userId==null) throw 401
  → 管理员接口: 由AdminInterceptor统一拦截，handler中只管业务
```

### 4.5 AI模块核心设计

```
AiService (接口, 6个方法)
├── recognizeImage(imageUrl) → 分类名
├── describeImage(imageUrl) → 描述文本
├── ocr(imageUrl) → 识别文字
├── enhanceDescription(imageUrl, userText) → 增强描述
├── auditContent(content) → 审核结果(PASS/REJECT)
└── getTextEmbedding(text) → 向量 (Claude返回空)

AiServiceFactory
└── getService() → 读 ai.provider 配置
    ├── "claude" → ClaudeServiceImpl (Anthropic Messages API, base64编码图片)
    └── 其他 → OpenAiServiceImpl (OpenAI兼容 /chat/completions，覆盖DeepSeek/Qwen)

MatchingServiceImpl (@Async("aiExecutor"))
└── 6维加权匹配: text(25%) + image_desc(25%) + OCR(15%) + category(15%) + location(10%) + time(10%)
    └── 阈值 ≥ 60% 保存为 MatchRecord，通知双方(前3条)
```

### 6.3 登录流程

```
打开 admin.html
  └─ 检查 localStorage.admin_token
     ├─ 有 → GET /api/admin/statistics 验证
     │   ├─ 成功 → 进入管理界面
     │   └─ 失败 → 清除token，显示登录框
     └─ 无 → 显示登录框
         └─ 输入密码 → POST /api/admin/login
            ├─ 成功 → 存token+localStorage，进入界面
            └─ 失败 → "管理员密码错误"
```

### 6.4 管理员登录后端

- `POST /api/admin/login` 接收 `{password: "xxx"}`，校验 `application.yml` 中 `admin.password`（默认 `admin123`）
- 查找DB中 `role=1` 的用户，若不存在自动创建（openid=`admin_user`，nickname=`管理员`）
- 并发安全性：INSERT失败时catch `DuplicateKeyException` 后重新查询
- 生成JWT + 缓存token和角色到Redis
- `WebMvcConfig` 排除 `/api/admin/login` 不被 AdminInterceptor 拦截
