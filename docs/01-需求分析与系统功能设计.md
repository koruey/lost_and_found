## 一、项目概述

### 1.1 项目名称

《基于多模态AI的校园失物招领微信小程序设计与实现》

### 1.2 项目背景

当前高校校园内失物招领存在以下痛点：

| 痛点 | 现状 |
|------|------|
| 信息分散 | 失物信息散布在微信群、QQ群、朋友圈、公告栏，缺乏统一平台 |
| 查找效率低 | 学生需要逐个群聊翻看历史消息，信息容易被刷掉 |
| 描述不准确 | 失主描述主观模糊，拾取者无法准确判断 |
| 图片无法利用 | 传统方式图片与文字分离，图片内容无法被检索 |
| 无法自动匹配 | 失物和招领信息各自发布，完全依赖人工比对 |

### 1.3 项目目标

设计并实现一个基于**多模态AI**的校园失物招领微信小程序，利用图像识别、OCR、自然语言处理等技术，自动完成物品分类、描述生成、图文理解和智能匹配，大幅提高失物找回效率。

### 1.4 目标用户

- **在校学生**：主要用户群体，发布失物/招领信息
- **教职工**：辅助用户群体
- **系统管理员**：平台管理与内容审核

## 二、功能性需求

### 2.1 用户端功能

#### 2.1.1 微信授权登录

| 编号 | F-01 |
|------|------|
| 名称 | 微信授权登录 |
| 描述 | 用户通过微信一键登录，获取微信昵称和头像 |
| 输入 | 微信授权 |
| 输出 | 登录成功，生成JWT Token |
| 规则 | 首次登录自动注册；Token过期自动刷新 |

**说明**：微信小程序已调整登录策略，静默登录即可获取openid，头像昵称通过用户填写或默认生成。本系统采用**wx.login获取code → 后端换取openid → 自动注册/登录 → 返回JWT**的方案。

#### 2.1.2 发布失物信息

| 编号 | F-02 |
|------|------|
| 名称 | 发布失物信息 |
| 描述 | 失主发布丢失物品的详细信息 |
| 字段 | 物品图片（1-9张）、物品标题、详细描述、丢失地点、丢失时间、物品分类、联系方式（可选是否公开） |
| 规则 | 图片必填（至少1张），标题2-30字，描述10-500字，分类必选 |

#### 2.1.3 发布招领信息

| 编号 | F-03 |
|------|------|
| 名称 | 发布招领信息 |
| 描述 | 拾取者发布捡到物品的信息 |
| 字段 | 物品图片（1-9张）、物品标题、详细描述、拾取地点、拾取时间、物品分类、联系方式 |
| 规则 | 同失物发布规则 |

#### 2.1.4 搜索与筛选

| 编号 | F-04 |
|------|------|
| 名称 | 搜索与筛选 |
| 描述 | 用户通过多种条件查找失物/招领信息 |
| 支持条件 | 关键词搜索、分类筛选、地点筛选、时间范围筛选、信息类型（失物/招领） |
| 排序方式 | 发布时间、匹配度（AI匹配场景） |

#### 2.1.5 物品详情

| 编号 | F-05 |
|------|------|
| 名称 | 物品详情查看 |
| 描述 | 查看失物/招领的完整信息 |
| 内容 | 图片轮播、物品信息、发布者信息、AI识别结果、相似物品推荐 |
| 交互 | 收藏、评论、联系发布者 |

#### 2.1.6 收藏

| 编号 | F-06 |
|------|------|
| 名称 | 收藏 |
| 描述 | 用户收藏感兴趣的物品信息 |
| 规则 | 可收藏/取消收藏；收藏列表按时间排序 |

#### 2.1.7 评论

| 编号 | F-07 |
|------|------|
| 名称 | 评论 |
| 描述 | 用户在物品详情下留言讨论 |
| 规则 | 评论长度1-200字；可删除自己的评论；AI自动审核违规内容 |

#### 2.1.8 消息通知

| 编号 | F-08 |
|------|------|
| 名称 | 消息通知 |
| 描述 | 系统推送重要消息给用户 |
| 类型 | 匹配通知（AI匹配到疑似物品）、评论通知、审核结果通知、系统公告 |
| 方式 | 小程序内消息列表 + 微信订阅消息（可选） |

#### 2.1.9 个人中心

| 编号 | F-09 |
|------|------|
| 名称 | 个人中心 |
| 描述 | 用户管理个人信息和发布记录 |
| 包含 | 个人资料、我发布的失物、我发布的招领、我的收藏、消息中心、关于我们 |

### 2.3 AI功能（核心创新）

#### 2.3.1 图片识别（物品分类）

| 编号 | AI-01 |
|------|------|
| 名称 | 图片物品识别 |
| 描述 | 上传图片后AI自动识别物品类别 |
| 分类 | 手机、耳机、钥匙、校园卡、钱包、书籍、雨伞、电脑、眼镜、水杯、身份证、衣物、背包、文具、其他 |
| 输出 | 分类结果 + 置信度 |

#### 2.3.2 图片描述生成

| 编号 | AI-02 |
|------|------|
| 名称 | 图片描述生成 |
| 描述 | AI分析图片，生成物品外观描述 |
| 输出 | 颜色、品牌、材质、外形特征等文字描述 |

#### 2.3.3 OCR文字识别

| 编号 | AI-03 |
|------|------|
| 名称 | OCR文字识别 |
| 描述 | 识别图片中的文字信息 |
| 适用 | 校园卡姓名学号、学生证信息、书籍封面、纸条内容 |
| 输出 | 识别到的文字内容 |

#### 2.3.4 图文联合理解

| 编号 | AI-04 |
|------|------|
| 名称 | 图文联合理解 |
| 描述 | 结合图片内容与用户输入文字，生成完整、规范的物品描述 |
| 输入 | 图片 + 用户原始描述 |
| 输出 | AI增强后的完整描述（补充颜色、特征、识别文字等） |

#### 2.3.5 智能匹配

| 编号 | AI-05 |
|------|------|
| 名称 | 智能匹配 |
| 描述 | 根据多维特征计算失物与招领的匹配度 |
| 匹配维度 | 图片特征相似度、文本语义相似度、OCR结果匹配、分类匹配、地点距离、时间关联 |
| 输出 | 匹配度分数 + 匹配理由 |

#### 2.3.6 AI分类

| 编号 | AI-06 |
|------|------|
| 名称 | AI自动分类 |
| 描述 | 发布时结合图片+描述自动确定物品分类 |
| 备注 | 与AI-01合并实现，AI-01输出分类即完成此功能 |

#### 2.3.7 AI内容审核

| 编号 | AI-07 |
|------|------|
| 名称 | AI内容审核 |
| 描述 | 自动检测违规内容 |
| 检测项 | 广告、色情低俗、辱骂、垃圾信息、涉政敏感 |

## 三、非功能性需求

### 3.1 性能要求

| 指标 | 要求 |
|------|------|
| 接口响应时间 | 普通接口 ≤ 500ms |
| AI接口响应时间 | ≤ 5s（AI调用耗时较长，采用异步处理） |
| 图片加载 | 支持缩略图 + 原图，缩略图 ≤ 200KB |
| 并发支持 | 支持100+用户同时使用 |

### 3.2 安全性

- JWT Token 认证，过期时间2小时
- 敏感信息（手机号）脱敏处理
- SQL注入防护（MyBatis Plus参数化查询）
- XSS防护（前端输入过滤）
- 图片上传类型校验
- API接口权限校验

### 3.3 可用性

- 界面简洁清晰，符合微信小程序设计规范
- 操作流程不超过3步完成核心功能
- 适配不同手机屏幕

### 3.4 可维护性

- 后端分层架构清晰
- 代码注释完整
- 接口文档自动生成（Knife4j）
- 统一异常处理、统一返回格式

## 六、业务流程

### 6.1 失物发布流程（AI增强）

```
用户拍照/选图
    │
    ▼
上传图片到服务器（MinIO）
    │
    ▼
调用AI服务（并行）：
├── 图片识别 → 物品类别
├── 图片描述 → 外观描述
└── OCR识别 → 文字提取
    │
    ▼
返回AI结果给用户确认/修改
    │
    ▼
用户补充/确认信息：
├── 标题（AI可自动生成建议）
├── 描述（AI图文联合理解生成完整描述）
├── 分类（AI已预选）
├── 地点
├── 时间
└── 联系方式
    │
    ▼
AI内容审核
    │
    ▼
提交 → 管理员审核 → 发布
```

### 6.2 智能匹配流程

```
新信息发布
    │
    ▼
提取特征向量：
├── 图片特征（视觉特征向量）
├── 文本特征（语义向量）
├── OCR文本
├── 分类
├── 地点
└── 时间
    │
    ▼
与对端信息库比对（失物↔招领）
    │
    ▼
计算多维匹配度
    │
    ▼
匹配度 > 阈值（如60%）→ 推送通知给双方
    │
    ▼
用户查看匹配结果
```
